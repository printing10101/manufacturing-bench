# 教训出处：DL-LNN 四阶段实验（2026-08）

本包每一条协议都来自真实实验的踩坑记录。完整实验细节见
灵境制造项目 `research/experiments/`（exp46-51）与结果文档。

## 教训 1：smoke 强信号不可信（S1/S7）

- exp47（门控 v1）smoke 显示 (0%,20%) 失配 −68% 强信号；**全量 5 seeds 下消失**
  （实为 −1.6%）——欠拟合假象。
- 教训：小规模 smoke 只验证管线，**结论一律以全量（多 seeds）为准**。
- 论文方法论章节素材："我们如何避免单次运行误报"。

## 教训 2：求解器不记录 = 不可复现（S2）

- torchdiffeq 安装后 LTCCell 默认走 dopri5（自适应步长），实测 **0.899 s/step
  vs Euler 0.010 s/step（慢 90 倍）**。
- 忘设 `_HAS_TORCHDIFFEQ=False` 的实验直接卡死 600s+（exp51 初版事故）。
- 教训：求解器必须显式声明并写入结果 JSON。

## 教训 3：近常数段 R² 失效（S4/S10）

- uniwear 真实磨损（exp50）：时间外推尾段磨损平坦，测试段目标方差占比
  0.0001-0.001 → 所有组 R²=−0.5~−20，但 MAE 相对磨损尺度仅 3-30%。
- 历史 sim2real R²=−30~−86 大概率同源机理：**负 R² 不是模型崩溃，
  是 R² 指标在近常数目标段不适用**（分母趋零）。
- 教训：报告 sim2real 结果前先跑 `NegativeR2Diagnoser`。

## 教训 4：作弊基线（S8）

- exp51 初版：Tlusty 基线用"无失配 Tlusty 预测由 Tlusty 生成的标签"——
  完美基线（Brier=0）暴露评估协议缺陷。修复：基线注入模态参数失配 δ=10%。
- 教训：解析基线必须模拟真实部署的系统误差，否则结论无意义。

## 教训 5：负面结果翻转（S9）

- 阶段 1 三连证伪（v1/v2/aug 门控都无法防御未见失配）——负面结果本身
  划定了能力边界，是论文"何时值得"判据的证据基础。
- 用户学术诚信原则：负面结果如实报告，翻转研究路线而非掩盖。

## 教训 6：指标与任务匹配（S10）

- 点回归任务：解析基线可靠 → DL 不必要（R²/PCC 为主）。
- 分布/风险任务（SLD 分布预测）：解析模型 σ≡0 信息论上无法表达不确定性
  → 需覆盖率/校准指标，R² 退居参考。
- 教训：先定任务表述，再选指标——任务表述本身是"DL 何时值得"的一维。
